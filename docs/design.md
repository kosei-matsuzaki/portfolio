# 見た目の規定

このサイトの見た目を決めているもの。**新しいブロックを足すときも、画面を直すときも
ここの値だけを使う。**色は `src/app/globals.css` の `@theme`、器は
`src/components/ui.tsx` が唯一の出どころで、画面にベタ書きしない。

規定を変えるときは `/design`。更新の手順は [operations.md](operations.md)。

## 方向

**日本語で読ませる作品ノート。色は作品自身から借りる。**

読むのは日本語話者の採用担当で、面接直前に 2 分だけ開く。だから和文の組みを設計対象にし、
色には仕事を 1 つだけ持たせる — **どの作品か**を示すこと。それ以外はすべて無彩色。

守るのは 4 点。

- **面ではなく罫線で区切る**：`bg-surface` のカードを積むのではなく、`border-t border-border` の
  行として並べる（Works・Research・Skills はすべてこの形）
- **左端に番号の段を作る**：セクション見出しの `§NN` も各行の通し番号も `RAIL_GRID` の左段に置く。
  §番号は Works=01 から始まり、最上部のヒーロー（`#about`）と末尾の学歴・資格は番号を持たない
- **並び順は「作品が先、経歴は後」**：2 分しか見ない人に先に届けるのは作品。
  学歴・資格はページの末尾に置く
- **角丸は使わない**：ボタン・バッジ・画像枠すべて直角。例外は 2 つだけ —
  箇条書きの ●（`rounded-full`）と、スマホ端末の図版枠（`Clip` の `shape="device"`）
- **色は作品の識別だけに使う**：リンクは色ではなく下線で示す。強調に色を使わない

### やらないこと

次の 5 つは、いまどの生成物にも出てくる既定形なので使わない。

| 使わない | 代わりに |
|---|---|
| 大文字の英字ラベル（`WORKS` などの eyebrow） | 日本語の見出しだけ。英字ラベルは置かない |
| 番号・数値・ラベルの等幅フォント | 本文書体。等幅は**インラインコードだけ** |
| リンク・ボタン末尾の `→` `↗` | 下線。外部リンクは小さい印を別に置く |
| 見出しの一語だけを色や斜体で強調する | 強調は語順と改行でつくる |
| 内容が順序でないのに付ける連番 | 作品の通し番号は**掲載順の目次番号**として残す（`§NN` も同じ） |

## 書体

| 役割 | 書体 | 理由 |
|---|---|---|
| 見出し・作品名 | Zen Old Mincho 600 | 和文の明朝を見出しに使う。日本語で読ませる意思をここで示す。**太さは 1 つだけ**（和文書体は 1 ウェイトで 122 ファイル・約 2.4MB） |
| 本文・UI | Zen Kaku Gothic New 400 / 500 | 画面本文向けに設計された和文ゴシック |
| インラインコード | JetBrains Mono 400 | **コードだけ。**ラベルにも数値にも使わない |

`next/font` がビルド時に自前配信する（`src/app/layout.tsx`）。和文は unicode-range で
分割配信されるので、必要な字だけが読み込まれる。

- 和文の詰めは `font-feature-settings: "palt"`
- 字送りは本文 `0.02em`、見出し `0.01em`
- 数値の桁を揃えたいのは比較表の数字だけ。そこに `tnum` を付ける（他には付けない）

## 字の尺度

**6 段しかない。中間値を作らない**（1 つ作ると際限なく増える）。

| 段 | ≥640px | <640px | 行間 | 用途 |
|---|---|---|---|---|
| `display` | 44px | 30px | 1.25 | ヒーローの見出し（`profile.tagline`）・作品詳細の作品名 |
| `h1` | 30px | 24px | 1.4 | セクション見出し |
| `h2` | 24px | 20px | 1.4 | 一覧の作品名 |
| `body` | 16px | 15px | 1.85 | 本文 |
| `small` | 14px | 13px | 1.7 | メタ・キャプション・ボタン |
| `micro` | 12px | 12px | 1.5 | バッジ |

和文の行間を 1.85 取るのは、欧文より字面が大きく行が詰まって見えるため。

## 色

`@theme` の外に色を書かない。地と面は無彩色寄りで、作品の色を濁らせない。

| トークン | 値 | 用途 |
|---|---|---|
| `--color-bg` | `#0a0b0e` | 地。和文を暗地で読ませるので黒に落とし切らない |
| `--color-surface` | `#0f1116` | 一段上げた面 |
| `--color-surface-2` | `#151820` | 図版の下地・チップ |
| `--color-border` | `#232733` | 罫線 |
| `--color-border-strong` | `#363c4b` | 強い罫線・ボタンの枠 |
| `--color-fg` | `#e9ecf1` | 本文 |
| `--color-muted` | `#9aa2b0` | 副文・サブタイトル |
| `--color-faint` | `#6b7382` | ラベル・キャプション。12px で潰れない下限 |

**アクセント色とカテゴリ色は持たない。**`--color-accent` と teal / violet / amber /
blue / pink は捨てた（作品と関係のない色分けだったため）。

### 作品の色

各作品は自分の画面から取った色を 1 つ持つ（`projects.ts` の `accent`）。
使うのは 4 か所だけ — 通し番号（`IndexNo`）・`RailDot`・「詳しく見る」の下線・
詳細ページの見出しの下に引く 1 本。**レールの縦罫線は無彩色のまま**（線が増えると
色が意味を失う）。

| 作品 | 色 | どこから取ったか |
|---|---|---|
| keiba-ai | `#eaa93e` | ダッシュボード唯一のアクセント（オレンジのボタンと強調） |
| fluid-lab | `#50c7d8` | 惑星の海。青緑がこの作品の主題 |
| gold-rush | `#ef6fbf` | 筐体のネオン管。金は keiba-ai と重なるのでネオンを採った |
| piano-studio | `#46e2ce` | 譜面エディタの UI アクセント |
| michishirube | `#81a6e4` | アプリの基調色 |
| tabishiori | `#6470c4` | 姉妹アプリなので michishirube と近い。**それが正しい** |
| chess-ai | `#6187c7` | 盤の青 |

画像を載せていない作品（mc-eso / automl-zero-llm / bandai-namco-workshop）は
`accent` を持たず、`--color-fg` が使われる。**借りる先が無いので色を作らない。**

作品を足したら、その画面から色を 1 つ選んで `accent` に書く。暗地で読めるよう
明度 0.58–0.70・彩度 0.45–0.80 の範囲に収める。**近い色になっても直さない** —
似た画面の作品は似た色になるのが正しい。

## 余白・最大幅・レスポンシブ

左右の余白と最大幅は **`ui.tsx` の `Container` / `GUTTER` に集約**している。
新しいブロックも必ず `<Container>` で包む（直接 `px-*` を書かない）。

| 種類 | 最大幅 | 用途 |
|---|---|---|
| `<Container>` | 1140px | トップページの各セクション・ヘッダー・フッター |
| `<Container width="read">` | 660px | 作品詳細ページ。16px の和文で約 38 字（推奨 30–45 字の内側） |

- 左右の余白（gutter）は `px-5 → sm:px-8 → lg:px-10` の 1 系統のみ
- セクションの上下は `py-14 sm:py-20` に統一（`Section` が持っている）
- 画面幅 768px 未満でヘッダーがハンバーガーに切り替わる（`MobileNav.tsx`）
- 一覧では技術を**アイコンのみ**（`TechIcons`）、詳細では**アイコン＋名前**（`TechChips`）

## 左段と縦罫線（レール）

セクション見出しの `§NN` も各行の通し番号も、幅 `5rem` の細い左段に入る。
**左段には番号しか置かない**。英字ラベル・カテゴリ・分類名をここに入れると幅が要り、
内容の左に余白が空きすぎる（一度そうして作り直した）。

縦罫線を引くのは **番号の付いた行（作品・研究・インターン）だけ**。
セクション見出し・学歴・資格・Skills の分類のような「箇条書きでないもの」には引かない
（引くと線が意味を持たなくなる）。

- `RAIL_GRID` … `md:grid-cols-[5rem_minmax(0,1fr)]`。**全ブロック共通**
- `RAIL` … 左段に付ける罫線と余白。**番号付きの行にだけ**付ける
- `RailDot` … 罫線の上に置く●。`relative` な要素の中で使う

狭い画面では罫線を出さず、素直に縦積みに戻る。

## 図版に動画を使う

作品の図版は静止画だけでなく、ループ再生する無音動画を使える。`projects.ts` で
`Media`（`poster` ＋ 任意の `video`）を書くと `Clip` が描画する。

```ts
media: {
  poster: "/images/<slug>/hero-poster.webp",
  video: "/video/<slug>/hero.mp4",   // 省略すると静止画だけ
  alt: "...",
  caption: "...",
},
bullets: [{ title: "...", text: "...", media: { poster, video, alt, caption } }],
```

再生の決まり:

- **一覧**は、ホバーできる端末ではホバー（フォーカス）中だけ再生する。触るまで動画を
  読み込まないので、マウスで見る人にとって一覧は軽いまま
- **ホバーできない端末（`hover: none`）では、一覧も画面に入ったら再生する。**
  ホバーを条件にしたままだと、スマホでは一覧の動画が一生再生されない。
  **代償は通信量**で、一覧を最後まで見ると動画が合計 7.5MB 落ちる。
  「動くものを作れる」がいちばん伝わらない状態と引き換えに、これを選んでいる
- **詳細ページ**は画面に入ったら再生・出たら停止
- どれも `preload="none"` で、実際に再生する直前まで `src` を差さない
- **自動再生しない条件は 2 つ** — `prefers-reduced-motion: reduce` と、
  通信量を節約する設定（`Save-Data`）。どちらも再生ボタンを出して手動に切り替える

動画は **1280×800・無音・mp4 (H.264)**。ポスターは同じ寸法の WebP で、
`npm run sizes` の対象なのでレイアウトのずれは起きない。

**スマホアプリだけは例外**。390×844 の縦長を 16:10 に収めると中身が読めないので、
`Media` に `portrait: true` を付けて実寸の比率のまま置く。

| 場所 | 見せ方 |
|---|---|
| 一覧のカード | `Plate`（方眼を敷いた台）の中に正方形で端末を立てる。他と高さが揃う |
| 詳細ページの主図版 | `Plate` の中に端末を置き、右に説明（`FIG. 01` ＋ キャプション）を添える |
| 箇条書きの図版 | 幅 260px の端末をそのまま置き、キャプションは下 |

## 動き

`data-reveal` を付けた要素が、画面に入ったときにフェードインする
（`Reveal.tsx` ＋ `globals.css` の `.motion-ready`）。

- 初期状態を隠すのは JS が動いたときだけなので、JS 無効でも本文は必ず見える
- `prefers-reduced-motion: reduce` では一切適用しない
- **これがページ唯一の自動再生の動き。**他に足さない

## 状態

ここを書かないと画面ごとに別々の答えになる。

| 状態 | 見え方 |
|---|---|
| 絞り込みで 0 件 | **起こさない。**分類のボタンは `works` から作るので、作品が 1 件も無い分類は出ない |
| 詳細から一覧へ戻る | 開いていた作品の位置（`#work-<slug>`）へ返す。絞り込みは覚えておくが、戻り先がその絞り込みで隠れるなら「すべて」に戻す |
| 表が画面幅に収まらない | 右端に地の色へ落ちる影を出す。切れていることを見えるようにする（狭い画面だけ） |
| 一覧の静止画サムネ | 狭い画面では枠を 4:3 に詰めて左上に寄せる。16:10 のままだと中の文字が潰れる |
| 動画が読めない | ポスター画像のまま。エラーは出さない（読み物として成立する） |
| `prefers-reduced-motion` | 自動再生なし・フェードなし。動画には再生ボタンを出す |
| JS 無効 | 本文・図版・リンクはすべて見える。絞り込みと動画だけが効かない |
| 長い作品名 | 折り返す。省略記号で切らない（誰の何かが分からなくなる） |
| 画像が 404 | `alt` が出る。枠は残す（レイアウトを崩さない） |

## 期間（period）の書き方

`projects.ts` の `period` は **開始年月〜終了年月** に統一する。

```
"2024年11月〜2025年1月"   同じ年をまたぐときは年を 2 回書く
"2026年6月〜7月"          同じ年なら年は 1 回
"2026年3月〜"             継続中は開始年月だけ
"2026年8月"               開始と終了が同じ月のときだけ 1 つ
```

「（継続開発中）」「（約3週間）」のような補足は入れない（継続中かは `〜` で分かる）。
年月は元リポジトリの最初と最後のコミットで裏を取ること。

## 文章の書き方

`projects.ts` に書くのは **何ができるか・何を工夫したか** で、開発の経過ではない。
「方向」に書いたとおり読む時間は短く、遠回しに言うぶんだけ届かなくなる。

- **遠回しに言わない。**「旅先で電波が無いのはよくあることなので、外へ出る通信は
  読み取りだけに絞りました」→「通信は必要最低限にとどめ、圏外でも開ける」
- **読む人の判断を変えない実装の細部は書かない**（金額を整数で持つ、といった話）。
  書くのは、そう決めた理由がそのまま設計の判断になっているときだけ
- **版ごとの変更履歴を並べない。**残すのは、そこから決めたこと。公開日・審査のような
  外向きの事実は 1〜2 文で足りる
- 1 セクション = 見出し ＋ 3 文前後、または短い箇条書き 2〜4 本
  （箇条書きが 1 本しかないなら本文に畳む）。
  **数字と、その数字が何を測った値かは削らない**（それが根拠になる）

詳細ページで等幅のインラインコードとして描画される（`RichText`）。
**等幅を使うのはここだけ。**それ以外の記法は解釈しない。
